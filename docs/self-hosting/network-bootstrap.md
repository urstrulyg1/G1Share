# Dynamic network bootstrap and TURN credentials

G1Viewer reads the provider configuration from:

`https://raw.githubusercontent.com/urstrulyg1/G1Viewer/main/config/network-bootstrap.json`

The application fetches this document at startup and refreshes its in-memory copy after the configured cache TTL. It uses the built-in public relay/STUN defaults if the HTTPS endpoint is unavailable or the response is invalid. Normal users should not need to configure a signaling URL.

## Bootstrap schema

`config/network-bootstrap.json` is the source-controlled provider list:

```json
{
  "schemaVersion": 1,
  "relayUrl": "https://ntfy.sh",
  "stunUrls": [
    "stun:stun.l.google.com:19302",
    "stun:stun.cloudflare.com:3478"
  ],
  "turnCredentialsUrl": null,
  "cacheTtlSeconds": 900
}
```

Only HTTPS relay and credential endpoints are accepted. STUN URLs must use the `stun:` or `stuns:` schemes. Environment variables remain available for self-hosting and testing; they override the corresponding dynamic defaults.

## TURN is required for reliable connectivity on restrictive networks

STUN can establish direct connections on many networks, but it cannot guarantee connectivity through symmetric NAT, some carrier-grade NATs, VPNs, and restrictive enterprise firewalls. Production deployment should operate a TURN service and a credential endpoint that returns short-lived credentials; do not put a TURN shared secret or static username/password in this public repository or in the desktop app.

When `turnCredentialsUrl` is set, the app requests the endpoint over HTTPS each time it builds ICE configuration. The endpoint must return this shape:

```json
{
  "expiresAt": "2026-10-16T19:00:00.000Z",
  "iceServers": [
    {
      "urls": [
        "turn:turn.example.org:3478?transport=udp",
        "turn:turn.example.org:3478?transport=tcp",
        "turns:turn.example.org:5349"
      ],
      "username": "short-lived-username",
      "credential": "short-lived-credential"
    }
  ]
}
```

Requirements:
- `expiresAt` must be in the future and no more than 24 hours away.
- Every URL must use `turn:` or `turns:`; the endpoint cannot add arbitrary STUN entries or arbitrary remote fetch URLs.
- Credentials must be generated by the TURN service (for example, Coturn REST API credentials derived server-side from a secret held only by the service).
- The endpoint should return `Cache-Control: no-store`, enforce HTTPS, rate-limit requests, and never log credential values.
- TURN relay capacity, egress cost, abuse controls, and availability must be monitored.

If the credential endpoint is unavailable, G1Viewer falls back to STUN/direct candidates so LAN and networks that permit direct WebRTC can still work. This fallback is intentional but does **not** promise that every network can connect.

## Release gate

The checked-in default bootstrap currently has `turnCredentialsUrl: null`. Therefore the app is device-ID-first and does not require manual signaling-server setup, but it is **not yet guaranteed to connect across every NAT/firewall**. Before advertising universal one-step internet connectivity, deploy and operate TURN plus the HTTPS credential endpoint, update the bootstrap, and validate real devices across restrictive networks.
